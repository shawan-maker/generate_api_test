## 三、用户管理「启用」失败定性（非本轮修复回归）

- 失败现象：`未找到菜单项: 启用`，两轮 UI 门禁同点位确定性复现。
- 根因：**操作顺序与业务前置依赖矛盾**——「启用」菜单项仅对冻结态行可见，而操作序列为「设置到期时间 → 启用 → 冻结」（启用排在冻结前），行正常态时菜单无此项。该顺序来自探测收集顺序（菜单 DOM 顺序），基线时代 UI 门禁通过依赖当时行恰处冻结态（探测残留脏数据）掩盖了此缺陷；本轮环境行状态正常即暴露。
- 本轮 form_filler 修复（selector 构建/字段去重）不涉及操作排序与行级菜单，与本失败无因果；两轮 UI 脚本均使用 11-18 基线生成物（本轮用户管理未重新生成 UI 脚本）。
- 修复方向（待决策）：crud_executor `ordered_actions` 按互斥对依赖排序（启用类反向状态操作排其正向操作后）——属「前置依赖全分析」原则的通用化改造，影响全部项目探测排序，需单独评估。
