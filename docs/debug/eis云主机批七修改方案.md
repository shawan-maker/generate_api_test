# EIS 云主机批七修改方案（r9 观察现象 + 终败问题源头治理）

> 日期：2026-11-25 ｜ 基线：r9 验收（成功 24/失败 5，35 分钟，尝试 48 次）
> 原则：**从源头解决（调度模型/判定结构/词表单源），不在 fallback 链上打补丁**；不改消息分类逻辑（用户拍板：提示信息判断保持不动）。
> 本文档只定方案，不改代码；不确定项列探针（§八），探针先行确认后再排实施。

## 一、核心诊断：三处结构性缺陷

r9 的 35 分钟与 48 次尝试中，"真正必要的业务执行"约 29 次；其余 19 次尝试（禁用盲试 12 + 确定性失败重试 5 + 误杀 2）与 ~10 分钟的无效等待（克隆锁阻塞期操作、tab 扫描超时、误跳页往返）全部源于三处结构问题：

### 缺陷 1：盲试模型——发起前不预检"当前是否可执行"
- 单操作入口 `_error_driven_retry`（crud_executor L2614，max_rounds=10）对每次调用固定走完整流程：装消息捕获器 → 搜索过滤 → 行定位 → hover 菜单 → 选项检查 → 失败记录 → 第 2 轮重试 → Vision → 终止。禁用跳过（skipped）单次成本 ~10s，双轮 ~20s。
- r9 实证：29 次 skipped 总计 ~4 分钟，重置密码/更新密钥对/修改Hostname 在 m/c/r 三阶段被同一"禁用"理由反复盲试。
- **源头**：可执行性预检必须在"发起尝试"之前——按钮 Vue disabled prop + marker 行存在性，两者都可 1-2s 内完成（禁用判定已有权威口径：Vue prop 而非样式类）。预检不过 → 不进尝试流程、直接交回调度器记 pending（等待状态窗口），成本从 ~20s 降到 ~2s。

### 缺陷 2：失败无记忆——"换状态也一样错"的失败被反复重试
- 修复 5 已建立 attempted_actions 白名单预算机制，且 cascade（L937）与 reconcile（L1205）都有预算检查——机制本身贯穿了。
- 但白名单 `TERMINAL_ERROR_TYPES`（const.py L90）只有 6 类：required_field_empty / form_validation / no_confirm_button / confirm_word_missing / no_fields / dialog_mismatch。**dialog_still_open 不在**——r9 重置密码 4 次 dialog_still_open 全部不入册，三处预算检查形同虚设。
- main 主循环入口无预算检查——创建镜像 3/3 耗尽后 main 仍执行第 4 次（L2815 累计 4/3）。
- **源头**：失败二分法（详见 §四与状态机冲突讨论）——确定性失败（换状态也不会好的）全阶段记忆拦截；状态性失败（换状态可能好的）保留状态机等待语义。

### 缺陷 3：提交/关闭按钮识别用"文本词表"，而 EIS 用"业务语义文本"
- SUBMIT_TEXTS=['提交','保存','确定','确认',...]——EIS 更新密钥对弹窗的提交按钮是"**更新并重启云主机**"（const.py L60 注释已记录），全词表不命中。
- 命中不了就落到 Primary 回退：`self.page.locator('button.el-button--primary').first` **无 scope 全页取第一个**（replay/form_filler.py L1514，JS 同样全文档 querySelectorAll）→ 页面工具栏"创建云主机"（el-button--primary）被误点 → 跳 createVm 页 → F6 无消息 URL 变化判"成功"（success_verifier L569 无角色约束）→ **更新密钥对 r9 从未真正提交过，是假成功**。
- CANCEL_TEXTS=['取消','Cancel','否'] 不含"关闭"——执行命令弹窗（只有"关闭"按钮）confirm=False 找不到目标，_close_dialog 兜底（X 按钮/Esc）也未生效（待探针 P-3）。
- **源头**：提交/关闭按钮识别以**弹窗容器结构信号**为主、文本词表为辅——提交按钮 = 活跃弹窗 footer 内的 primary 类按钮（排除否定前缀）；关闭 = 弹窗 headerbtn X / footer 关闭/取消词表（补"关闭"）。Primary 回退必须 scope 限定活跃弹窗容器；无活跃弹窗时禁用 Primary 回退（页面级操作本就不该由"弹窗提交"回退兜底，落 no_submit_button 正确终态）。

## 二、逐项源头方案

### F1（A1）克隆产物就绪等待——用户拍板方向
**语义**：克隆 = 资源供给型操作（与"创建云主机"同类但多一个后置窗口：产物从"克隆中"到稳定态）。克隆成功后，先等克隆产物 VM 就绪，再继续任何后续操作。

1. **产物名获取**：克隆弹窗"名称"字段的 fill value 即克隆产物名（r9 已证：L1437 编辑字段: 名称 = test595657）。在 `_do_generic_operation` 克隆成功分支记录 `context["clone_product"] = 名称字段值`。无需从列表反推。
2. **就绪等待**（P-1 定案后判据）：成功后、返回调度器前，轮询：SEARCH-FIRST 按产物名过滤 → **产物行出现且状态列（复用 `_read_row_status` L619）不含"克隆中"字样 → 放行**；行未出现或状态含"克隆中" → sleep 重查。间隔 10s，上限 180s（P-1 实证 VM 过渡分钟级，180s 足够；r9 克隆产物已清理，"克隆中"精确文案未捕获，行出现为主信号）。
3. **位置**：STATE-CHANGE 级联批中克隆 ✓ 后、执行批内下一按钮前（源头：级联调度器在克隆成功后设 `provisioning_wait`，批内后续操作与批间转移均先等它清零）。主循环同理（克隆也可能在 main 阶段执行）。
4. **超时**：不挂死——超时记 warning + 状态文本入产物，继续执行（与 QGA 等待"一次性有界"同模式，参照 L2660-2676）。
5. **与消息分类无关**：`captured:success:克隆云主机成功` 判定本身正确不动；"克隆中, 请等待克隆完成"的 error 样式 toast 判 success 也不再发生（因为等待后不会再撞）。这正是源头解法优于改词表的地方——EIS 把进行中提示挂 error 样式属环境怪癖，词表判定是通用逻辑不该为单一环境特化。

### F2（A2+A5）调度统一预检门
1. 新增 `_preflight_executable(page, btn, marker)`：① marker 行存在（SEARCH-FIRST 快查）② 菜单项 Vue disabled prop（既有权威口径）。任一不过 → 返回 pending 原因，不进 `_error_driven_retry`。
2. 接线三处入口：main 循环 verify 单操作前、STATE-CHANGE 批内每按钮前、STATE-RECONCILE R1 业务执行前（L1216 前）。预检不过的记 `wait_reason`（禁用/行不存在），仍留 pending 等状态机窗口——**不改变"遍历所有业务"语义**，只消除"明知不可执行的完整流程成本"。
3. 内部重试轮（L2614 循环）：同错误连续 2 轮即终止的现状保留，但第 1 轮为 skipped/禁用/row_not_found 时**不再进第 2 轮**（状态 10 秒内不可能翻转，第二轮必然同败）——r9 实证 12 组"第 2 轮 skipped"全部与第 1 轮同错。
4. 重启类收益核算：r9 重启 5 次尝试（1 真 4 盲），预检后 = 4 次预检（~8s 总计）+ 1 次真执行；硬重启 3 次尝试同理。

### F3（A2）失败二分法 + 记忆全阶段贯穿
1. **白名单扩充**（const.TERMINAL_ERROR_TYPES 单源）：加 `dialog_still_open`（提交未生效：登录名错值/表单校验拒绝，换状态必同败）、`readonly_dialog_error`、`api_error`（EIS 语义 error toast，如"QGA 未就绪"另有专门等待豁免，见下）。
2. **状态性失败豁免表**（新增 const.STATE_PENDING_ERROR_TEXTS）：错误文本含状态语义（'QGA 未就绪'、'克隆中'、'请等待'、'未就绪'、'正在'）→ **不入册**，保留状态机等待——这是与状态机不冲突的关键边界（§四）。
3. **main 循环预算接线**：verify 单操作入口加 `_attempted_exhausted` 检查（与 cascade L937/reconcile L1205 同一出口），耗尽即跳过并记"预算耗尽"。
4. 预算上限维持 3 次（MAX_LIFETIME_ATTEMPTS）。

### F4（A3+B1 关联）提交按钮结构化识别 + Primary 回退 scope 收紧
1. Primary 回退 scope 限定：`submit_form_v2` 已有 `_fp_before`（点击前活跃弹窗指纹）——Primary 回退的 locator 与 JS querySelectorAll 均加 scope=该弹窗 wrapper 容器；`_fp_before` 为空（无活跃弹窗）→ Primary 回退直接禁用，返回 no_submit_button。
2. 弹窗 footer 提交识别主判据补强：活跃弹窗 footer 内 `el-button--primary`（EIS 实证："更新并重启云主机"是 primary 样式，探针 P-2 确认）+ 否定前缀排除（已有）。文本词表保留为第一优先（对提交/确定/保存类通用系统零变化）。
3. 该修复同时拯救更新密钥对（假成功→真提交）与所有 EIS 业务语义按钮的系统。
4. **不做**：不扩 SUBMIT_TEXTS 词表收"更新并重启云主机"（那是打补丁——下个系统还会有别的语义文本；结构判据一次治本）。

### F5（A4）只读弹窗关闭链补全
1. CANCEL_TEXTS 补'关闭'（单源 const）——只读查看型弹窗关闭即成功（L5528 注释本就这么定义，只是词表漏了 EIS 的"关闭"按钮文本）。
2. `_close_dialog` 兜底失效根因已探针定案（P-3）：执行命令弹窗 headerbtn X 存在且 visible、**Esc 实测可关**——非结构性不可关，根因是 CANCEL_TEXTS 找不到目标按钮后兜底链未在窗口内触发；F5 词表补全后主链直接命中，**`_close_dialog` 兜底保持现状不改**。
3. read_complete 成功后的关闭动作保留现有链（L5503-5505），仅词表与兜底修正。

### F6（B3）导航型菜单项分流
1. 分流点：`_do_generic_operation` 的 `_observe_post_click` 检测到 URL 跳转且**无弹窗弹出**时——判定"菜单项=导航链接"语义：跳转目标 URL 含 marker（如 vmDetail/.../test595047）→ 直接判导航成功（操作=点击菜单项，交互已完整），**不进 EDIT-FLOW 探索**（navigation_executor 找提交按钮路径对导航型是错路径）。
2. 网络配置实证：L2854 跳转 vmDetail 含 marker → 现走 EDIT-FLOW 扫 9 tabs×2 轮全超时（~4 分钟）；分流后 ~5s 判成功。
3. 与删除等"提交后跳列表页"区分：那些有弹窗+提交动作在先，不落此分支（无弹窗跳转条件天然隔离）。
4. F6 URL 变化判成功（success_verifier L569）保留不动——本方案是让正确路径更快到达它，不是放宽它。

### F7（B1）重置密码凭证回填
1. 回显/凭证类字段（登录名）不做 name_pattern 生成：fill_helpers 生成规则加"凭证回显类"分支——字段已有 currentValue（弹窗打开时 EIS 回显了实际登录名）→ 保留原值不覆盖。
2. 判据：字段 label 含'登录名'/'用户名' 且弹窗打开时已有非空 currentValue → 保持不动（用户既有验收规则"有默认值的字段一律保持默认"的自然延伸：**回显值也是"默认值"**）。
3. EIS 重置密码弹窗打开时登录名**已实测回显**（P-4 定案：value='root'）——直接走"回显保留"分支，无需创建轮凭证注入通道（作为后备保留在设计中，不实施）。
4. 修复后 dialog_still_open 不再发生，F3 的 dialog_still_open 入册成为防御性兜底而非主路径。

### F8（B2）弹窗归属判据放宽
1. 3a 判据从"操作名是弹窗 title 连续子串"放宽为 **token 覆盖匹配**：操作名分词（'创建镜像'→['创建','镜像']）后全部 token 在 title 中出现（'创建云主机镜像'含两者）→ 判归属成立。
2. 主体词白名单（'云主机'/'主机'/'实例'/'虚拟机'）插入不破坏匹配——单源 const。
3. 防误判边界保留：完全不重叠（如操作'删除'对 title'创建云主机镜像'）仍判 mismatch 清残留——r9 的 A4 清理残留机制不受影响。

### F9（B4）成功信号优先
1. verifier 裁决序：**已捕获 success 通知 > DOM field 红字**。当前 field 红字（密码不能为空，来自残留弹窗或空标题弹窗内的校验文本）推翻了已捕获的"已退出运维模式"成功通知。
2. 实现于 success_verifier 判定序（有 success 消息 → 直接成功返回，不再扫 field 红字），不新增词表不改消息分类——是判定优先级修正。
3. 互斥对佐证通道保留：菜单项消失（visible=not_found）作为成功旁证记入产物 notes，不做判定依据（避免把真失败也判成功——成功通知为主判据，菜单消失仅佐证）。

### 不修（记录）
- B5 标签管理：菜单项随行状态动态显隐的收集时序漂移，低频且 F2 预检可把成本降到 ~2s（预检发现菜单项 not_found 即返回 pending），不值得专项修。
- 更新密钥对 main 阶段禁用（Stopped 态不可执行）正常——F2 后它只在 reconcile 状态窗口真执行一次。

## 三、与状态机的冲突讨论（用户问题 2 正面回答）

用户观点："不涉及状态切换的业务操作，按钮不为 disabled 则表示能操作，出错了就记录下来，换到其他状态还是一样会出错"——**基本正确，但需二分**：

| 失败类别 | 例子（r9 实证） | 换状态会好吗 | 处理 |
|----------|----------------|--------------|------|
| 确定性失败 | 重置密码登录名错值、创建镜像归属误杀、表单校验拒绝 | **不会**（错误与行状态无关） | F3 全阶段记忆，预算 3 次后永跳过 |
| 状态性失败 | QGA 未就绪（开机后 QGA 起来才好）、克隆中锁、行过渡态禁用 | **会**（正是状态机存在的原因） | 保留等待语义：F1/F2 预检+就绪等待，不入失败记忆 |

- **不冲突的机制边界**：状态机（STATE-RECONCILE 转移边 + settle 等待）管"**何时可执行**"——预检门（F2）正是它的前置快速通道；失败记忆（F3）管"**是否值得再执行**"——只在确定性失败时收紧。两者正交：状态性失败不入册，状态机窗口照常驱动；确定性失败入册后状态机也不再浪费窗口。
- **用户担心的反面**：EIS 有"换状态确实会好"的失败（修改Hostname 在 r9 是 QGA 未就绪 error + 禁用双态失败，Running+QGA 就绪后成功）——这就是为什么不能用"出错就永久记录"的一刀切，必须文本语义二分。
- 落地把关：状态性豁免词表单源（const.STATE_PENDING_ERROR_TEXTS），入册白名单单源（TERMINAL_ERROR_TYPES），两表都不在执行器里散写。

### 探针定案（2026-11-25 实测，载体 test598388）

**载体准备**：r9 marker VM（test595047/test595657）已被环境清理，探针前受控创建载体 test598388（命名空间 test-smoke、ubuntu22.04-iso、网络 autoapi-vlan-net9762(10.251.10.0/24)共享），探针开始时已"运行中"。附创建链实证：createVm 页选完镜像版本后**系统盘 size 自动级联填充 20、pvc-type 自动填"性能优化型"且 disabled 锁定**——"级联自动填充态勿强制填充"判据的活证据（r9 playbook 系统盘(下拉)用 check_default_value 而非 click_first 的原因）。

- **P-1 定案**：克隆弹窗 title='云主机克隆'，footer=[取消(default), 确定(primary)]——**标准取消词命中，无关闭链缺口**；字段=名称(空/必填/请输入名称)、存储类型(select 空)、**登录名 root 回显**、登录密码×2/确认密码(空)。状态列文案"启动中"→"运行中"过渡在分钟级内完成；**r9 克隆产物已被清理，"克隆中"精确文案未捕获**——F1 等待判据调整为：SEARCH-FIRST 按产物名过滤 + **产物行出现且状态列不含"克隆中"字样即放行**（行出现为产物已建立的主信号），等待上限维持 180s、超时不挂死。探针 JS 路径 `dd.__vue__.command.row.status` 全 20 轮返回 None——该路径在 EIS 行级 dropdown 上不可用，F1 实施时以 `_read_row_status`（L619）既有口径为准（探针负结果仅针对探针自身 JS 路径，非机制负结果）。
- **P-2 定案**：更新密钥对弹窗 footer=[放弃更新(el-button--default), **更新并重启云主机(el-button--primary is-disabled, vueDisabled=true)**]——**提交按钮是 primary 实锤，F4 主判据成立**；空选密钥对时提交按钮 disabled（选完即解除）；**footer 无'取消'**（取消词表全不命中+A3 否定前缀'放弃更新'实锤）；headerbtn X visible=true 可关闭；body 另有密钥对刷新按钮（custom-icon-button refresh-btn）。弹窗内唯一表单字段=密钥对(select, 空)。
