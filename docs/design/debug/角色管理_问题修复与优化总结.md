# 角色管理模块探测 - 问题修复与优化总结

## 📋 背景

在对角色管理模块 (`/estack/web/estack/user-center/user-manage/role`) 进行探测时，发现了 5 个影响自动化探测成功率的问题。这些问题不仅影响角色管理，还会影响其他使用 RESTful 风格 API 的模块。

---

## 🐛 发现的问题与修复

### 问题 1: 自动登录凭据配置错误
**文件**: `module_discovery/gen_test.py:597`

**现象**: 生成的测试脚本在 cookie 过期后无法自动重新登录

**原因**: `"credentials": {}` 导致 `AuthSession` 认为没有凭据，拒绝触发自动登录

**修复**:
```python
# 修复前
"credentials": {}

# 修复后
"credentials": {
    "username": username,
    "password": password,
}
```

**影响**: 所有新生成的测试脚本（包括用户管理、角色管理等）

---

### 问题 2: 端点分类器不支持 RESTful 风格路径
**文件**: `module_discovery/endpoint_classifier.py`

**现象**: `/policies`、`/roles` 等 RESTful 资源路径被错误分类为 `other_post`

**原因**: 分类器只识别带明确动作词的路径（如 `/create`、`/update`），不识别 RESTful 风格

**修复**: 添加 RESTful 兜底逻辑（优先级 ⑥）
```python
# ⑥ RESTful 资源路径兜底：POST /resources = 创建，PUT /resources/{id} = 更新
if method == "POST" and not any(k in p for k in ("/list", "/page", "/search", "/check")):
    # 排除已知的基础设施 API（菜单、主题、字典等）
    if not any(k in p for k in ("/menu/", "/theme", "/favorite", "/dynamic-dictionary",
                                 "/notice/", "/access-log", "/system-theme")):
        return "create"
if method == "PUT":
    return "update"
if method == "PATCH":
    return "update"
```

**验证**:
```
POST   /estack/api/estack/draco/v1/policies               -> create ✅
PUT    /estack/api/estack/draco/v1/policies/abc123        -> update ✅
DELETE /estack/api/estack/draco/v1/policies/abc123        -> delete ✅
GET    /estack/api/estack/draco/v1/policies/list          -> query  ✅
```

**影响**: 所有使用 RESTful API 的模块

### 问题 3: 工具栏按钮扫描逻辑缺陷
**文件**: `module_discovery/capture_apis.py:65-67`

**现象**: Stage 2 捕获到的工具栏按钮数量为 0，但 Stage 1 已正确识别

**原因**: `button_driver.scan_toolbar_buttons()` 使用硬编码 CSS 选择器，不兼容所有页面布局

**修复**: 从 UI 结果加载工具栏按钮
```python
# 修复前
toolbar_buttons = await button_driver.scan_toolbar_buttons()

# 修复后
toolbar_buttons = [b["text"] for b in ui_result.get("toolbar_buttons", [])]
```

**影响**: Stage 2 API 捕获流程

### 问题 4: 日志格式不符合 HTML 报告解析器
**文件**: `projects/ecm-compute/flows/v1.0.0/角色管理_API测试.py`

**现象**: HTML 报告为空（无内容）

**原因**: 日志输出格式为 `Step 1: 创建`，但 `report_html.py` 期望 `[创建] /api/path`

**修复**: 修改日志格式
```python
# 修复前
print("\nStep 1: 创建")

# 修复后
print("\n[创建] /estack/api/estack/draco/v1/policies")
```

**验证**:
```

```

**影响**: 角色管理测试脚本

### 问题 5: estack 策略文档格式要求
**文件**: 文档记录（`docs/design/角色管理API测试_经验总结.md`）

**发现**:
- `policyDocument` 必须是 JSON 字符串（不是对象）
- 关键字必须小写（`version`、`statement`、`effect`）
- 不是 AWS IAM 风格

**示例**:
```python
policy_doc = json.dumps({
    "version": "v1",
    "statement": [{
        "effect": "ALLOW",
        "action": ["USER:ListUsers", "USER:ListRoles"],
        "resource": ["*"]
    }]
})
```

**影响**: 涉及策略/权限配置的模块

## 📝 经验教训

### 1. 凭据配置必须显式
`AuthSession` 不会从函数参数自动继承凭据，必须在 profile 中显式声明。

### 2. RESTful API 需要特殊处理
不是所有系统都使用 `/create`、`/update` 等动作词路径，需要支持 `POST /resources`、`PUT /resources/{id}` 等 RESTful 风格。

### 3. 避免重复逻辑
UI 扫描和按钮驱动不应重复扫描同一元素，应复用 UI 结果。

### 4. 日志格式是契约
`report_html.py` 定义了日志格式契约，所有生成的脚本必须遵守。

### 5. 探测优先原则
先手动探测 API 行为，再编写自动化脚本，避免基于假设编写代码。
