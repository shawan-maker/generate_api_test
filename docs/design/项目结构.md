# API 自动化测试项目 · 结构说明（API_AI_test）

> 适用对象：新接手本项目、或要把这套框架迁移到另一个"无接口文档的后台系统"的工程师。
> 读完本文你应能：**建好项目 profile、跑通自动发现、拿到 Postman 集合、看懂报告、知道改哪个文件**。
> 完整技术方案见 `方案设计.md`；实地勘探结论见 `实地勘探报告.md`（estack 实测，首个 profile 参考）。

---

## 1. 项目概览

| 项 | 内容 |
|---|---|
| 定位 | **多项目框架**：`projects/<id>/` 下每个被测系统独立；estack 是当前第一个 profile，并非唯一 |
| 被测系统(示例) | estack 控制台 `https://console-estack-syyhb.cmecloud.cn`（无 Swagger/OpenAPI，已实测） |
| 技术栈 | **Python 3.11+**（venv 隔离，呼应 EcsCloud 的 node-v20 教训，绝不用系统 Python） |
| 关键依赖 | `httpx`、`playwright`（巡游+滑块）、`opencv-python`（缺口识别，复用 EcsCloud `identify_gap`）、`pydantic v2`/`jsonschema`、`jsonpath-ng`、`pytest`+`xdist`+`rerunfailures`、`schemathesis`（可选） |
| 核心思想 | **通过 = 真成功 + 状态校验**：CRUD 用例必须回查（创建→能查到 / 删除→查不到），校验业务码 `success==true && !errorCode`，并校验操作后业务状态（激活/可用等） |
| 分层要点 | **API 层（`api/`，薄、可独立调用、正常异常共用）** 与 **脚本层（`flows/`+`tests/`，编排+断言）** 彻底分离 |
| 产物 | 可导入 Apifox/Postman 的集合（OpenAPI 3.1 + Postman v2.1）、可跑的 pytest 回归、单文件 HTML 报告、按项目隔离的知识库 |

## 4. 用例脚本结构（你每天写的东西）

每个用例就是一个 pytest 函数，**调用 API 层函数 + 脚本层编排 + 真成功断言**：

```python
# projects/estack/tests/用户中心/test_user_crud.py
import pytest
from projects.estack.api import draco.user as api
from projects.estack.flows.crud_flow import CrudFlow
from lib.assertions import assert_crud_success

def test_create_user_and_cleanup():
    flow = CrudFlow("user", api)
    # 通过=真成功：创建→回查能查到；删除→回查查不到
    created = flow.create({"name": "{{faker.word}}", "role": "viewer"})
    assert_crud_success(api, "user", "list", expect_id=created["id"])
    # ④ 状态校验：创建后状态须为激活/可用（来自 kb/state_semantics.json）
    flow.assert_state("createUser", created["id"])
    flow.delete(created["id"])
    assert_crud_success(api, "user", "detail", expect_missing=created["id"])
```

**API 层 vs 脚本层（为什么分两层）：**

```python
# projects/estack/api/draco/user.py —— API 层：薄，无断言，正常异常共用
def create_user(c, *, name: str, **extra) -> ApiResponse:
    return c.request("POST", "/estack/api/estack/draco/v1/users", json={"name": name, **extra})

# 正常
create_user(c, name="AT_user1")
# 异常（同一函数，测空名期望失败）—— 这就是"同一接口直接调用来测正常异常"
create_user(c, name="")
```

**关键约定：**
- 用例文件按**菜单/模块**归档（对应 Postman 目录树），文件名 `test_<resource>_crud.py`。
- 所有"通过判定"收口到 `lib/assertions.py`，**禁止各用例自己 `if status==200: pass`**（那是假通过）。
- 跨用例数据用 `lib/context.py` 传递（`context.set/get`），禁止硬编码 id。
- 自动创建的资源**必须带 `AT_` 前缀**（来自 `globals.yaml` 的 `resource_prefix`），供 `orphan_cleaner.py` 回收。

## 5. 运行入口速查（详见 `RUNNERS.md`）

> 所有命令带 `--project estack`（或 `ACTIVE_PROJECT=estack` 环境变量），默认取 `config/settings.py` 里配置的 active project。

| 场景 | 命令（在 `.venv` 激活后） |
|---|---|
| 新建项目 profile | `python -m config.settings init --id estack --url <初始URL>` |
| 自动发现（巡游+归并） | `python -m discovery.playwright_crawl --project estack --url <初始URL>` |
| HAR 导入发现 | `python -m discovery.har_import <file.har> --project estack` |
| 生成 API 层 | `python -m generators.gen_api_layer --project estack` |
| 导出 Postman 集合 | `python -m generators.gen_postman --project estack` |
| 导出 OpenAPI（Apifox） | `python -m generators.gen_openapi --project estack` |
| 只读用例并发跑 | `pytest projects/estack/tests/ -m "not crud" -n auto` |
| CRUD 链串行跑 | `pytest projects/estack/tests/ -m crud`（强制串行） |
| 单用例调试 | `pytest projects/estack/tests/用户中心/test_user_crud.py::test_create_user_and_cleanup -s` |
| 孤儿清理 | `python -m lib.orphan_cleaner --project estack --prefix AT_` |

**铁律：** 所有命令在 `.venv` 里跑；登录需滑块，首次会弹浏览器解滑块并缓存 token；敏感信息（token/密码）**只在 profile.yaml 里放 env var 引用，绝不落明文**，且所有捕获流量入库前过 `lib/desensitize.py`。

## 6. 质量红线（"通过"判定标准）

- **创建类** → 回查 list/detail 能查到该资源（不能只信 200）。
- **更新类** → 回查 detail，字段值 == 新值。
- **删除类** → 回查 404/空，或 list 中不存在。
- **异步任务** → 轮询状态字段到终态。
- **业务码** → 必须 `success==true && !errorCode`（estack 响应形如 `{traceId,success,message,errorCode,entity}`）；**HTTP 200 但 `success:false` 一律判失败**。
- **状态校验** → ④ 操作后须达 `state_semantics.json` 期望状态（激活/可用等）；无状态字段则退化为存在性校验。
- **脱敏** → token/密码/手机号等入库前必须脱敏，否则视为严重违规。
- **信任分级** → 来自 JS 静态分析的不可信候选（`trusted:false`）必须人工确认才入库。

## 7. 快速上手 5 步（以 estack 为例）

1. 激活环境：`.venv\Scripts\activate`（Windows）/ `source .venv/bin/activate`。
2. 建 profile：`python -m config.settings init --id estack --url https://console-estack-syyhb.cmecloud.cn` → 填 `profile.yaml`（base_url / SID / 凭据 env var 引用）。首次运行会用滑块登录并缓存 token。
3. 跑发现：`python -m discovery.playwright_crawl --project estack --url <初始URL>` → 生成 `kb/api_catalog.json` + `kb/function_*.json` + `output/captures/*`。
4. 生成 API 层 + 导出：`python -m generators.gen_api_layer --project estack` → `python -m generators.gen_postman` 导入 Apifox 看接口；`gen_openapi` 保真度更高。
5. 跑用例 / 看报告：只读并发 `pytest projects/estack/tests/ -m "not crud" -n auto`；失败看 `kb/failure_ledger.json` 的 `verdict`，根因写进 `failure_overrides.json`。
