# 登录鉴权与自动重登机制（EcsCloud）

> 适用目录：`D:\Mobile\EcsCloud`
> 目标读者：需要"日常用 cookie 跑用例，cookie 失效才自动滑块登录并写回"的维护者。
> 本文是**当前实现的如实梳理**（含已生效的设计与已知的坑），不是目标态设计。

---

## 0. 一句话结论

- **设计意图（已实现）**：cookie 优先；cookie 有效就一直用，只有失效才走滑块登录，登录成功后把 cookie 写回对应环境的 cookie 文件。
- **已支持双环境（dw / ip）**：通过环境变量 `ESTACK_TARGET` 切换。DW（`console-estack.dw.cmecloud.cn`，`cookies.json`）为默认；IP（`10.151.37.249`，`cookies.ip.json`）已接通自动登录/滑块/写回链路（详见 §6）。两套环境的 cookie 文件、登录地址、探测页**完全隔离**，互不覆盖。
- **"每次新客户端打开都重复尝试登录"的根因已修复**：原本 `run_all_with_auth.js` 在**启动浏览器之前**就调用鉴权（无 `page` → 探测恒失败 → 窗口外必重登）；现已改为先 `chromium.launch()` 再带 `page` 鉴权，窗口外也能真探测、只在 cookie 真失效时才登录（详见 §5）。

## 2. 核心调用链（cookie 优先 → 探测 → 滑块 → 写回）

```
ensureValidAuth({ browser, ctx, page, forceProbe, ttlMs, username, password })
        │
        ├─(前置) AUTO_LOGIN !== '1'  → 直接放行，不探测不登录
        │
        ├─ 1) isFresh(ttlMs)?  ── cookies.meta.json.savedAt 在窗口内 且 cookies.json 非空
        │        └─ 是 → { usedCache:true }  ✅ 跳过探测，直接复用（最快路径）
        │
        ├─ 2) probeSession(page)  ── 访问 PROBE_URL，URL 含 /login 即失效
        │        └─ 有效 → 刷新 savedAt，{ valid:true }  ✅ 复用
        │
        └─ 3) 证伪 → loginWithRetry() → loginAndSaveCookies()
                   └─ 滑块登录成功 → 写回对应环境的 cookie 文件（dw→cookies.json / ip→cookies.ip.json）+ 刷新 meta.savedAt
                   └─ 返回 { relogged:true, valid:true }
```

**关键事实**：
- 步骤 1（新鲜度）**不需要 page**；步骤 2（探测）**必须有 page**，否则 `probeSession` 直接返回 `false`（`lib/session.js` 第 91 行 `if (!page) return false;`）。
- 步骤 3 的 `loginAndSaveCookies` 会**自己 launch 一个浏览器**完成滑块登录，再 `context.cookies()` 落盘到 `cookies.json`。

## 3. 关键函数签名与如何调用

### 3.1 `lib/session.js`

```js
// 统一鉴权入口
ensureValidAuth({ browser, ctx, page, forceProbe=false, ttlMs, username, password })
// → Promise<{ valid, relogged, usedCache, ctx, page }>

// 新鲜度：cookie 在窗口内且 cookies.json 非空
isFresh(ttlMs = DEFAULT_TTL_MS)            // → boolean
freshAgeSec()                             // → 距 savedAt 的秒数

// 服务端探测（必须有 page！）
probeSession(page, { url = PROBE_URL, waitMs = 2500 })  // → Promise<boolean>

// 滑块登录（外层重试 2 次）
loginWithRetry(username, password, options={}, { maxRetries=2 })  // → Promise<boolean>

// 写回 cookie + 刷新 meta.savedAt
saveCookies(cookies)                      // 同时写 cookies.json 与 cookies.meta.json
```

### 3.2 `scripts/login.js`

```js
// 在已有 page 上完成滑块登录；返回是否成功（URL 含 /portal）
loginToEStack(page, username, password, options={})        // → Promise<boolean>

// 自带浏览器跑完登录并把 cookie 落盘到 cookieFile（默认 cookies.json）
loginAndSaveCookies(username, password, options={})        // → Promise<boolean>
// options.loginUrl 默认 'https://console-estack.dw.cmecloud.cn/estack/web/estack/login'
```

### 3.3 程序内调用范式

```js
const session = require('./lib/session');

// 推荐：带上 browser/ctx/page，让探测真正生效（避免无谓登录）
const auth = await session.ensureValidAuth({ browser, ctx, page, username, password });
if (!auth.valid) throw new Error('登录态获取失败');

// 强制重新探测（不依赖新鲜度缓存）
await session.ensureValidAuth({ browser, ctx, page, forceProbe: true });

// 仅判断、不登录
if (session.isFresh()) { /* cookie 还很新 */ }
```

## 4. 环境变量

| 变量 | 作用 | 默认值 |
|---|---|---|
| `ESTACK_TARGET` | **目标环境切换**：`dw`（默认）/ `ip`（10.151.37.249 内网）。决定 cookie 文件、登录地址、探测页 | `dw` |
| `AUTO_LOGIN` | 总开关；`=1` 才探测/登录，否则直接放行（`run_all_with_auth.js` 在拿到账号后会自动设为 `1`） | 未设置 |
| `AUTO_LOGIN_USER` | 自动登录用户名（dw 用管理员；ip 用 `jcyz213-test`） | 空 |
| `AUTO_LOGIN_PASS` | 自动登录密码 | 空 |
| `AUTH_FRESH_TTL_MS` | 新鲜度窗口（ms）；窗口内跳过探测 | `1800000`（30 分钟） |
| `HEADLESS` | `=1` 无头；影响 `loginAndSaveCookies` 是否开可见浏览器 | 非 1 = 可见 |
| `PROBE_URL` | 覆盖探测页（需登录、失效即跳 `/login`）；不同环境受保护页路径可能不同 | 见各环境 `CFG.PROBE_URL` |
| `LOGIN_URL` | 覆盖登录页地址 | 见各环境 `CFG.LOGIN_URL` |
| `LOGIN_SUCCESS_KEYWORD` | 登录成功后落地页关键字（用于判定成功） | `/portal` |

## 5. "每次新客户端打开都重复尝试登录" —— 根因与修复（已修复）

### 5.1 根因（为什么以前一定会重复）

`scripts/run_all_with_auth.js` 在**启动共享浏览器之前**就做了首步鉴权：

```js
// 旧代码 —— 注意：这里没有传 browser/ctx/page
const auth = await session.ensureValidAuth({ username, password });
// 之后才 chromium.launch(...) + setSharedBrowser(browser)
```

于是进入 `ensureValidAuth` 时 `page === undefined`：
- 步骤 1 `isFresh()`：取决于 `cookies.meta.json.savedAt` 是否在 **30 分钟**窗口内。
  - **窗口内**：返回 `usedCache`，不登录 ✅
  - **窗口外**：`isFresh` 为 false → 走到步骤 2 `probeSession(undefined)` → 因无 page **直接返回 false** → 走到步骤 3 **滑块登录**。

结论：**只要两次运行间隔超过 30 分钟，新进程必走滑块登录**。与 cookie 在服务端是否真的失效无关。

> 实测（修复前）：`cookies.meta.json.savedAt = 2026-08-21 13:39（北京时间）`，距今约 1.7 小时 > 30 分钟 → `isFresh` 已为 false → 每次新客户端打开都会触发滑块重登。

### 5.2 修复（已落地）

`scripts/run_all_with_auth.js` 已改为**先启动浏览器、再带 page 鉴权**：

```js
// 新代码：先 launch 浏览器 + 建 auth 上下文/页面，再鉴权
const browser = await chromium.launch({ ... });
setSharedBrowser(browser);
const authCtx = await browser.newContext({ viewport: { width: 1920, height: 1000 } });
await authCtx.addCookies(session.loadCookiesSafe());
const authPage = await authCtx.newPage();
// 关键：传入 page → 窗口外也能走「真·服务端探测」，cookie 仍有效就不重登
const auth = await session.ensureValidAuth({ browser, ctx: authCtx, page: authPage, username, password });
```

效果验证（本地 mock 服务模拟环境，见 `scripts/_verify_ip_auth.js`）：
- 带 page + 服务端判定有效 → `valid:true, relogged:false, 登录分支调用次数: 0`（**不盲目重登**）
- 无 page（旧顺序）→ `登录分支调用次数: 2`（盲目走登录，即旧 bug 行为）

长任务中途的周期刷新（`run_all_with_auth.js`）也已改为传入 `browser + probeCtx/probePage`，窗口外同样走真探测。

### 5.3 其它会"看起来像重复登录"的情况

- cookie 文件内容不完整：当某次只写出部分 cookie，`isFresh()` 的防御逻辑（cookie 文件非空才认为新鲜）可能判定为"不可复用"，从而重登。IP 环境用独立的 `cookies.ip.json`，避免与 DW 互相污染。
- 若 `ESTACK_TARGET` 与 `cookies.ip.json` 实际环境不匹配（如 cookie 是 DW 的却用 `ip` 跑），探测必失败 → 触发重登。确保 cookie 与目标环境一致。

## 6. 双环境支持（dw / ip，已接通）

通过 `ESTACK_TARGET` 切换，两个环境的代码链路**已完全接通且相互隔离**：

| 维度 | DW 环境（`ESTACK_TARGET=dw`，默认） | IP 环境（`ESTACK_TARGET=ip`，`10.151.37.249`） |
|---|---|---|
| 域名/地址 | `console-estack.dw.cmecloud.cn` | `10.151.37.249` |
| 账号 | `estack-tenant-admin-0808`（管理员） | `jcyz213-test`（普通员） |
| 登录地址 | `…/estack/web/estack/login` | `https://10.151.37.249/estack/web/estack/login` |
| 探测页 | `…/estack/web/vpc-console/vpcList` | `https://10.151.37.249/estack/web/estack/portal` |
| cookie 落点 | `output/config/cookies.json`（DW 域） | `output/config/cookies.ip.json`（domain `10.151.37.249`） |
| meta 落点 | `output/config/cookies.meta.json` | `output/config/cookies.ip.meta.json` |
| 自动登录 | ✅ 滑块重登 + 写回 | ✅ 已接通（同链路，目标按环境切换） |
| 会话维持 | `cookies.json` + 批跑时重登 | `cookies.ip.json` + 批跑时重登；`keep_alive.js` 另做保活续命 |

**实现要点**（`lib/session.js` 的 `resolveTarget()`）：
- `ESTACK_TARGET` 在模块加载时解析出 `CFG`（BASE_URL / LOGIN_URL / PROBE_URL / COOKIE_FILE / META_FILE / cookieDomain / SUCCESS_KEYWORD）。
- `pageHelper.js`、`login.js`、`run_all_with_auth.js`、`run_with_auth.js` 均改为读取 `session.CFG`，不再硬编码 DW。
- IP 的 cookie 用 `domain: 10.151.37.249`（IP 不能套 `.cmecloud.cn` 通配，否则访问时不发送 cookie = 等于没登录）。

**含义**：
1. "在 IP 上日常用 cookie 操作、失效自动滑块重登并写回"这一目的**现已支持**：`set ESTACK_TARGET=ip` 即可。
2. `keep_alive.js` 仍守 IP 做保活续命（每 15 分钟，内嵌 cookie，非滑块、不写回），与自动登录链路并存、互补。
